# Troubleshooting Notes

## Lab 52 – Security Tool Interference Investigation

## Issue 1 – Defender Exclusion Already Existed

### Problem

The lab directory may already appear in the Defender exclusion list.

### Cause

A previous test or administrative configuration may have added the same path.

### Resolution

Check the baseline before changing anything:

```powershell
Get-MpPreference |
Select-Object ExclusionPath, ExclusionProcess, ExclusionExtension
```

If `C:\SecurityToolLab` is already present, do not treat the existing entry as evidence generated by this lab.

Document it as a pre-existing configuration.

---

## Issue 2 – Add-MpPreference Command Fails

### Problem

`Add-MpPreference` does not execute successfully.

### Possible Causes

- PowerShell was not opened as Administrator.
- Microsoft Defender configuration is managed by policy.
- Tamper protection or endpoint-management controls prevent the change.
- The Defender cmdlets are unavailable.

### Resolution

Check:

```powershell
Get-Command Add-MpPreference
```

Then verify the PowerShell session has administrative privileges.

Do not attempt to bypass enterprise security controls.

---

## Issue 3 – Event ID 5007 Not Visible

### Problem

The Defender configuration changed, but Event ID 5007 could not be found.

### Possible Causes

- Event collection delay
- Defender Operational log not enabled or available
- Event log filtering
- Configuration-management interference

### Resolution

Open:

```text
Event Viewer
→ Applications and Services Logs
→ Microsoft
→ Windows Defender
→ Operational
```

Search around the exact time the configuration was changed.

If the event is still unavailable, document the missing telemetry.

---

## Issue 4 – PowerShell Process Event Not Found

### Problem

The Defender change is visible, but the PowerShell process that made the change is not immediately visible.

### Possible Causes

- Event log retention
- Audit configuration
- Sysmon not running
- Query time range too broad or narrow

### Resolution

Check Sysmon:

```powershell
Get-Service Sysmon64
```

Then review:

```text
Sysmon → Operational → Event ID 1
```

Also check Windows Security Event ID 4688.

---

## Issue 5 – PowerShell Event ID 4104 Not Available

### Problem

No Script Block Logging event can be found.

### Cause

PowerShell Script Block Logging may not be enabled on the endpoint.

### Resolution

Treat 4104 as optional supporting evidence.

Use:

- Sysmon Event ID 1
- Security Event ID 4688
- Defender Event ID 5007
- Wazuh telemetry

Do not assume the command was absent simply because 4104 is unavailable.

---

## Issue 6 – Wazuh Does Not Show Event 5007

### Problem

The Defender event is visible locally but not in Wazuh Discover.

### Possible Causes

- Defender Operational channel not being collected
- Wazuh collection delay
- Decoder/field differences
- Search query too restrictive

### Resolution

Start broad:

```text
agent.name: DESKTOP-9MMM37V
```

Then search:

```text
5007
```

Inspect the actual event fields and use the field names present in the indexed document.

---

## Issue 7 – Wazuh Search Returns Too Many Events

### Problem

The endpoint generates many unrelated events.

### Resolution

Narrow the search using:

```text
agent.name: DESKTOP-9MMM37V AND 5007
```

Then:

```text
agent.name: DESKTOP-9MMM37V AND powershell.exe
```

Use the exact investigation time window where possible.

---

## Issue 8 – Defender Protection State Appears Different After Testing

### Problem

The post-investigation Defender state does not appear identical to the initial baseline.

### Resolution

Compare:

```powershell
Get-MpComputerStatus |
Select-Object `
AMServiceEnabled,
AntivirusEnabled,
RealTimeProtectionEnabled,
BehaviorMonitorEnabled,
IoavProtectionEnabled,
AntispywareEnabled
```

with the initial baseline.

If the only intentional change was the lab exclusion, verify that the exclusion has been removed.

---

## Issue 9 – Lab Exclusion Remains Present

### Problem

`C:\SecurityToolLab` remains in the Defender exclusion list after the investigation.

### Resolution

Remove it:

```powershell
Remove-MpPreference -ExclusionPath "C:\SecurityToolLab"
```

Verify:

```powershell
Get-MpPreference |
Select-Object ExclusionPath
```

The lab exclusion should no longer be present.

---

## Issue 10 – Lab Directory Cannot Be Deleted

### Problem

`C:\SecurityToolLab` cannot be removed.

### Possible Cause

A file or PowerShell process may still have the directory open.

### Resolution

Close any PowerShell windows or processes using the directory, then run:

```powershell
Remove-Item "C:\SecurityToolLab" -Recurse -Force
```

Verify:

```powershell
Test-Path "C:\SecurityToolLab"
```

Expected:

```text
False
```

---

# Lessons Learned

- Always capture the security baseline before making a configuration change.
- Event ID 5007 is valuable for Defender configuration-change investigations.
- Process telemetry is needed to determine how the configuration was changed.
- Missing telemetry should be recorded as an evidence limitation.
- Wazuh searches should be narrowed gradually.
- A security configuration change is not automatically malicious.
- Always distinguish legitimate administration from potential defense evasion.
- Restore the original security configuration after controlled testing.
